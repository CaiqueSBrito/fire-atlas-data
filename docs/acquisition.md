# FIRMS CSV acquisition and receipts

This module downloads or imports **real CSV bytes**, then preserves them without changing the existing normalization contract. It does not create historical observations, infer sensor products, or invent archive download endpoints. It uses only the Python standard library.

## Verified upstream access contract

The following official pages were read while implementing this module:

- [FIRMS Archive Download](https://firms.modaps.eosdis.nasa.gov/download/): observations older than the last seven days can be requested as CSV, shapefile or JSON. The request interface requires Earthdata authentication or an emailed login code; FIRMS emails download instructions after processing the request. NRT records are replaced by standard science quality records as those become available, with approximately five months' lag. The page lists MODIS Collection 6.1 coverage from November 2000, VIIRS S-NPP from January 2012, NOAA-20 from April 2018, and NOAA-21 from March 2023. Availability is product-dependent, not guaranteed by this client.
- [FIRMS Area API](https://firms.modaps.eosdis.nasa.gov/api/area/): the documented CSV route is `/api/area/csv/[MAP_KEY]/[SOURCE]/[AREA_COORDINATES]/[DAY_RANGE]`, optionally followed by `/[DATE]`. Days must be 1–5. Area is `world` or `west,south,east,north`. Without a date it requests today and the preceding days; with a date it requests that date through date + days − 1. The page documents a free MAP_KEY and a 5,000-transactions/10-minute limit, with request costs potentially exceeding one transaction. This module does not implement retries, rate-limit scheduling, or a multi-year crawler.

Supported product declarations are `MODIS_NRT`, `MODIS_SP`, `VIIRS_SNPP_NRT`, `VIIRS_SNPP_SP`, `VIIRS_NOAA20_NRT`, `VIIRS_NOAA20_SP`, `VIIRS_NOAA21_NRT`, and `VIIRS_NOAA21_SP`. `_SP` means standard/scientific processing; `_NRT` means NRT and can include RT/URT observations. The official API also offers Landsat, which is outside this MODIS/VIIRS module's scope.

**Reading these documentation pages is not authenticated archive access.** No authenticated archive download or Area API data fetch was performed during implementation: no authorized archive link or MAP_KEY was supplied. Whether a particular historical request is available must be checked with FIRMS and the operator's access. An HTTP login page or an API error is not accepted as data.

## Commands

Run from the repository with the existing project environment (`uv run` may prefix these commands). The acquisition CLI is separate from the unchanged normalization CLI.

### Historical archive: explicit authorized HTTPS URL

First request CSV through the official archive interface and complete its authentication flow. Use an actual direct CSV download URL from those instructions. No guessed yearly or archive URL is generated by this code.

```sh
python -m fire_atlas_data.acquisition history \
  --url "$FIRMS_ARCHIVE_CSV_URL" \
  --product VIIRS_NOAA20_SP --processing scientific \
  --output-dir output/raw/noaa20-archive-receipt
```

`FIRMS_ARCHIVE_CSV_URL` must be set by the operator to a real authorized HTTPS CSV URL; this is not an endpoint template. The client can follow HTTPS redirects, but does not automate Earthdata sign-in, use browser cookies, or request an archive job. Links requiring unavailable authenticated sessions will fail. Use local import if the operator must download with a browser/authenticated client instead. Protect shell history/process visibility when a signed URL itself is sensitive; the receipt and application error output do not retain the complete URL.

### Recent Area API

Set the free key outside the command arguments. For example, the following reads it without placing its literal value in the shell command history:

```sh
read -r -s FIRMS_MAP_KEY
export FIRMS_MAP_KEY
python -m fire_atlas_data.acquisition area \
  --product VIIRS_NOAA20_NRT --area=-48,-17,-46,-15 --days 5 \
  --output-dir output/raw/noaa20-recent-receipt
unset FIRMS_MAP_KEY
```

Use `--key-env NAME` for another environment variable. No key CLI argument exists. The key is necessarily included in the official HTTPS request path but is redacted from saved URLs; remote exception details and response bodies are never printed. Area API redirects are refused to avoid forwarding credentials to another endpoint.

An explicit date uses the documented **forward** range semantics:

```sh
python -m fire_atlas_data.acquisition area \
  --product MODIS_SP --area=world --date 2020-09-01 --days 5 \
  --output-dir output/raw/modis-dated-receipt
```

This dated command is syntax, not a claim that this request was exercised or that the requested product/date is available to the operator. Check [FIRMS data availability](https://firms.modaps.eosdis.nasa.gov/api/data_availability/) and the service's access rules. `--area=...` avoids argparse interpreting a negative western longitude as another option. Bounding boxes must be ordered and within longitude/latitude bounds; split antimeridian-crossing requests manually.

### Import a CSV already obtained locally

```sh
python -m fire_atlas_data.acquisition import /path/to/obtained.csv \
  --product VIIRS_NOAA20_NRT --processing nrt \
  --output-dir output/raw/noaa20-local-receipt
```

`--source-url HTTPS_URL` is optional provenance for local import and is sanitized, not fetched or verified. The source file is only read, never renamed or rewritten. The receipt is for **now**: an old observation date does not backdate receipt, and no historical receipt time can be supplied. `downloaded_at_utc` is null for local import because the original download time is unknown.

## What is published

Every output directory must be new; existing files, empty directories and symlinks are refused. Each successful acquisition publishes:

- `raw.csv`: exact input/download bytes, including original line endings and any UTF-8 BOM;
- `manifest.json`: SHA256, byte count, CSV columns and row count, actual UTC receipt time, download completion time for remote downloads, declared product and processing class, method, sanitized URL and Area API request parameters.

The receipt marks processing classification as operator-declared, **not scientifically verified**. Archive URLs retain only their HTTPS origin and a redacted path: signed credentials may occur in paths as well as query strings. Area URLs retain the public request parameters but redact the MAP_KEY. Query strings, fragments and embedded credentials are never saved. Raw CSV content itself is intentionally not sanitized or rewritten.

Transfers stream in bounded chunks into a same-filesystem staging directory, compute SHA256 during copying, and are checked as UTF-8 CSV with unique required observation columns and consistently sized rows. CSV syntax/content checks do not validate scientific values or prove that data came from NASA. HTML/JSON responses, textual API errors, unexpected HTTP status/content type, malformed CSV, and mismatched Content-Length are rejected. A header-only FIRMS CSV is accepted as zero observations, not as proof of no fire. Partial downloads are cleaned up.

Completed files are published with atomic hard links into a newly reserved directory, without replacing existing files. The manifest is linked last and is the **commit marker**: consumers must require it before consuming `raw.csv`. Publication of the pair is not a single directory-rename transaction. An abrupt process/power loss after raw publication but before manifest publication can leave an uncommitted output directory; inspect and move it aside manually rather than overwriting it. Normal failures remove this operation's partial files. The output volume must support same-filesystem hard links.

## Normalization and scientific limitations

The existing `python -m fire_atlas_data normalize` command still accepts **only the existing NRT MODIS/VIIRS product names**. Acquisition can preserve a declared historical `_SP` scientific CSV, but `_SP` normalization is not implemented and is not silently relabeled as `_NRT`. Therefore historical scientific ingestion is supported **through raw-byte acquisition and provenance only**, not as a demonstrated end-to-end historical Parquet pipeline. For an actual NRT CSV, the existing normalization interface remains usable:

```sh
python -m fire_atlas_data normalize output/raw/noaa20-local-receipt/raw.csv \
  --source-product VIIRS_NOAA20_NRT \
  --output-dir output/noaa20-normalized
```

Acquisition receipt time is not automatically assigned to the normalized `available_at` field, and cannot recover the historical moment a detection became available. That field remains unknown under the existing normalizer. The real local normalized dataset currently spans September 1–October 22, 2026 only; no historical years or model validation are created by this downloader. Observations are thermal detections, not calibrated fire probabilities or independently verified fire events.

Offline tests in `tests/test_acquisition.py` describe the engineering contract using mocked HTTP and local files. They do not demonstrate live authentication, historical availability, or scientific correctness. They were not run during this implementation; the integrating agent should run them with the consolidated checks.
